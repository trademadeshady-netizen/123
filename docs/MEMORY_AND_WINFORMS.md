# WinForms и чтение позиции из памяти

## Состояние

Игра: TrinityCore WotLK 3.3.5a (указана пользователем). Версия сервера не задаёт адреса клиентского процесса. Точная сборка и смещения клиента ожидают подтверждения. Готового профиля и проверенных значений адресов в проекте нет. Этот документ описывает механизм настройки, а не заявляет совместимость с конкретным Wow.exe.

В Windows из корня репозитория:

```powershell
dotnet build
dotnet run --project winforms/HerbBot.WinForms.csproj
```

Окно: выбор процесса Wow.exe, обновление списка, подключение профиля, список маршрутов, запись и завершение записи, Старт/Стоп, зацикливание и импорт Gatherer. Выберите нужный PID, затем профиль JSON. После подключения и начала записи нажимайте R: позиция добавляется в `routes/<имя>.json`. <!-- coderabbit-ai-generated:v1 -->

## Идентификация клиента

Профиль содержит точную `clientFileVersion` из свойств Wow.exe и `clientSha256` (64 hex). Выберите тот же исполняемый файл, который запущен. Например, в PowerShell:

```powershell
(Get-Item 'C:\path\Wow.exe').VersionInfo.FileVersion
(Get-FileHash 'C:\path\Wow.exe' -Algorithm SHA256).Hash
```

Сравниваются имя процесса `Wow`, версия файла и SHA-256 файла на диске; PE должен быть x86 (I386/PE32). Указатель и числа читаются как little endian uint32/float32/int32. Это проверка профиля по файлу, а не доказательство идентичности уже загруженных страниц памяти; состояние клиента и смещения всё равно требуют независимой проверки. Процесс открывается с правами PROCESS_VM_READ и PROCESS_QUERY_LIMITED_INFORMATION. Память не записывается. При отказе доступа показывается ошибка Windows; права не повышаются автоматически.

## Формат профиля

Сохраните JSON и укажите его кнопкой подключения. `null` ниже — обязательные к замене поля, не рабочие адреса:

```json
{
  "gameVersion": "3.3.5a",
  "clientFileVersion": "УКАЖИТЕ_ТОЧНУЮ_ВЕРСИЮ_ФАЙЛА",
  "clientSha256": "УКАЖИТЕ_SHA256",
  "x": { "rootRva": null, "dereferenceOffsets": null, "finalOffset": null },
  "y": { "rootRva": null, "dereferenceOffsets": null, "finalOffset": null },
  "z": { "rootRva": null, "dereferenceOffsets": null, "finalOffset": null },
  "mapId": { "rootRva": null, "dereferenceOffsets": null, "finalOffset": null }
}
```

Смещения записываются целыми десятичными числами, допускаются отрицательные значения. `rootRva` — смещение от загруженной базы основного модуля Wow.exe. Алгоритм каждой цепочки: начать с `base + rootRva`; для каждого элемента `dereferenceOffsets` прочитать 32-битный указатель по текущему адресу, затем прибавить данный элемент; после цикла прибавить `finalOffset` и прочитать 4 байта значения. Пустой массив `[]` означает прямой адрес внутри модуля. До 16 разыменований. В X/Y/Z ожидаются мировые координаты float32, в MapId — int32. Эти цепочки поддерживают **только прямые адреса и цепочки указателей**; поиск по списку объектов с сопоставлением GUID должен реализовываться отдельным провайдером. Не используйте координаты зоны 0–1 в качестве мировых координат.

При чтении цепочки и mapId проверяются повторно, чтобы отбрасывать снимки при смене указателя или карты. Координаты проверяются на конечность и ограничены абсолютным значением 100000; mapId — 0..100000. Это не атомарный снимок: координаты могут измениться между чтениями. Нулевой указатель, выход за диапазон x86, неполное чтение, неверный профиль, завершение процесса или ошибка доступа не создают точку маршрута. Проверки не доказывают корректность чисел при ошибочных смещениях: проверьте позицию и mapId в нескольких зонах, в том числе после загрузки мира и переподключения клиента.

## Проверка

`dotnet test` проверяет адресные цепочки, запись точки в маршрут, смену карты и указателя, некорректные данные и ошибки чтения на имитации памяти. Сборка Windows target выполнена из Linux; реальное окно, Windows API, Wow.exe и физическая R требуют проверки на Windows. При нескольких клиентах PID выбирается вручную.
