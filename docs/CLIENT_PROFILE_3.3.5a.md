# ClientProfile 3.3.5a: статус и проверка

**Все адреса НЕ ПОДТВЕРЖДЕНЫ.** В репозитории нет клиентского Wow.exe или проверенного профиля. TrinityCore — сервер: версия сервера не доказывает адреса в клиенте. Числовые адреса в unit-тестах синтетические и не предназначены для игры.

## Схема JSON

ClientProfile сохраняет совместимость MemoryProfile. Поля: gameVersion=3.3.5a, build (метаданные), clientFileVersion (проверяется), clientSha256 (проверяется), readTimeoutMs=500, playerObject, x/y/z/mapId/guid/rotation, isMounted/isFlying/isInCombat/isGhost и sources (источник каждого значения).

Все цепочки: `{ "rootRva": null, "dereferenceOffsets": [], "finalOffset": null, "relativeToPlayer": false }`. null означает, что адрес требуется установить. Поля с null не могут использоваться для чтения. Начало цепочки — фактическая база модуля + rootRva; каждый элемент массива означает прочитать uint32-указатель и прибавить элемент. В конце добавляется finalOffset. При relativeToPlayer=true начало — результат независимой цепочки playerObject вместо базы модуля. PlayerObject не должен ссылаться сам на себя. Смещения JSON десятичные, не hex. Поле флага: `{ "address": <цепочка>, "mask": <uint32 маска> }`; считается true при любом установленном бите маски. Пустая/нулевая маска запрещена.

База модуля определяется Windows при подключении и кэшируется в WindowsProcessMemory.ModuleBase до отключения. В JSON фиксированная база не нужна из-за релокации; OffsetScanner выводит фактическую базу. X/Y/Z/Rotation — float32; MapId — int32, GUID — uint64 little endian. Build пока информационный: совместимость ограничивают точная версия файла, SHA-256 и PE32/I386.

## ObjectManager: схема, источники и статус

**НЕ ПОДТВЕРЖДЕНО на реальном клиенте.** `profiles/client.template.json` содержит null для адресов, смещений, GameObjectType и маски. RecordSize=0 запрещает сканирование до заполнения профиля. Номера в `ObjectScannerTests` — синтетические адреса. Никакие найденные в серверном TrinityCore константы не объявляются смещениями клиента.

| Поле JSON | Значение/семантика | Источник и статус |
|---|---|---|
| objectManager.manager | AddressChain от фактической базы модуля; может опираться на playerObject | Требуется реверс конкретного Wow.exe; НЕ ПОДТВЕРЖДЕНО |
| firstOffset, lastOffset | uint32 указатели по manager+offset; lastOffset=null означает конец по нулевому next | Требуется реверс; НЕ ПОДТВЕРЖДЕНО |
| traversal, nextOffset | linked: uint32 next в записи; только явная схема, без догадок о sentinel/тегах | Требуется эксперимент; НЕ ПОДТВЕРЖДЕНО |
| countOffset, stride | array: first указывает на первую запись, count — uint32 по manager+countOffset, stride в байтах не меньше recordSize | Поддерживаемый вариант схемы HerbBot; не утверждение о WotLK |
| recordSize, lastInclusive | Размер доступной записи; включать или исключать last | Требуется реверс; НЕ ПОДТВЕРЖДЕНО |
| guid | uint64 little endian | Смещение требуется установить; сверить GUID конкретной ноды |
| type, gameObjectType | uint32 и ожидаемое значение GameObject | Оба значения НЕ ПОДТВЕРЖДЕНЫ; серверные enum не доказывают layout клиента |
| entry | uint32, допустимый положительный int32; whitelist числовых групп HERB из Gatherer.lua | Источник whitelist: `GatherItems[continent][zone][entry].gtype`; смещение НЕ ПОДТВЕРЖДЕНО |
| x/y/z | float32 мировые координаты | Требуется реверс/сравнение с серверным spawn; НЕ ПОДТВЕРЖДЕНО |
| flags, dynamicFlags | uint32, читаются независимо | Смещения и значения НЕ ПОДТВЕРЖДЕНЫ |
| herbMask, herbFlagField | Дополнительный фильтр по flags либо dynamicFlags; null маски означает только whitelist entry | Универсальный «бит травы» не установлен. Нельзя подставлять выдуманную маску. Нулевая маска запрещена |
| maxObjects=10000, timeoutMs=500 | Ограничители затрат сканера | Политика безопасности чтения HerbBot, не значения WRobot |
| health/maxHealth/speed | AddressChain; int32/int32/float32 | Дополнительные поля полного игрового адаптера, НЕ ПОДТВЕРЖДЕНЫ; без них сбор не стартует |

Каждое поле записи имеет `{offset:null,pointerOffsets:[]}`. Без указателей offset относительно начала записи. При `pointerOffsets:[a,b]`: прочитать uint32 по object+a, затем uint32 по полученному адресу+b, затем добавить offset. Это позволяет описать внешние descriptors без адресов в C#. Прямые поля и первый указатель обязаны помещаться в recordSize; внешний descriptor проверяется чтением адреса, а не фиктивным размером. JSON использует десятичные числа.

`MemoryObjectScanner` использует тот же `IReadOnlyProcessMemory` и `MemoryPositionProvider`, что и позиция. Проверяет диапазон x86, длину чтения, число переходов, размер записи, циклы, лимит объектов, бюджет времени, конечность/границы XYZ, GUID до/после, смену manager/head/mapId. Некорректный снимок отдельной ноды (NaN, GUID=0/сменился, неизвестный entry) пропускается; ошибка страницы/частичное чтение прерывает **весь** снимок исключением. Частичный список не выдаётся за полный. Ограничитель времени кооперативный: синхронный ReadProcessMemory не прерывается. Повторное чтение GUID/head не делает снимок атомарным; полнота обхода требует ручной проверки.

### Проверка новых полей на игре

1. Зафиксировать build, FileVersion, SHA-256 Wow.exe; сделать копию шаблона в `profiles/client.json`. Получить кандидаты layout реверсом именно этого файла; записать адрес источника/метод/дату в sources для каждого поля.
2. На тестовом сервере выбрать известную траву и контрольную MINE. Через серверные данные spawn получить **entry и world XYZ**, затем сверить entry с числовой группой HERB в Gatherer.lua. В текущем Gatherer нет имён и world Z/mapId: сравнение по name или нормализованным XY не доказывает смещения.
3. Запустить `dotnet run --project tools/OffsetScanner -- <PID> profiles/client.json <player_GUID_hex> <mapId> Gatherer.lua`. Получить 20 снимков с интервалом 500 мс. Подойти к траве издалека, остановиться рядом, собрать, отойти. При необходимости повторить несколько запусков (10 секунд может быть мало).
4. В `offset-report.json` сравнить `objectManager.objects`: GUID/entry/type/flags/dynamicFlags/XYZ; `candidateListChanged` должен отражать вход/выход травы из видимости, minimumDistance при сборе — близость к игроку. Эти два признака — кандидаты подтверждения, не автоматическая верификация layout. Фильтр entry не проверяет пропущенные объекты; сверить **число и идентичность** трав с сервером. Проверить, что контрольная MINE не попала в HERB.
5. Для каждого флага снять значения до/после сбора, респавна, выделения и изменения доступности. Если однозначная маска травы не установлена, оставить herbMask=null и указать фильтрацию по HERB entry. Нельзя выбирать маску по одному объекту.
6. Повторить при смене карты, перезаходе и новом GUID на том же spawn. Удалить траву во время чтения: допустимы пропуск битой ноды либо явная ошибка снимка, но не падение приложения и не движение по мусорным координатам.
7. Приложить отчёты и серверные наблюдения к sources. Только после независимого сопоставления пометить конкретные поля «проверено»; пока все адреса остаются **ТРЕБУЕТ ЭКСПЕРИМЕНТА**.

Ни реальная игра, ни Windows ReadProcessMemory/ObjectManager в этой среде не проверялись. OffsetScanner проверяет заполненные кандидаты, автоматического поиска неизвестных адресов не выполняет.

PID и GUID/mapId замените реальными значениями. Утилита проверяет кандидаты из профиля, **не ищет адреса автоматически**. Откройте игру, получите GUID через /dump, запустите команду, двигайтесь и меняйте высоту 10 секунд. Будут напечатаны 20 снимков; `offset-report.json` содержит наблюдения, сравнение GUID/mapId и изменения по каждой оси. Код 0 означает прохождение этих ограниченных проверок; флаги и Rotation требуют ручного сравнения с действиями. Код 1 — несовпадение/ошибка/нет изменения хотя бы по одной оси, код 2 — неверные аргументы. Не объявляйте профиль подтверждённым лишь по коду 0. Сохраните отчёты после смены карты, персонажа и перезапуска клиента и укажите их в sources.

SafeProcessHandle освобождается при Stop/закрытии; читаются только PROCESS_VM_READ. Завершение процесса и частичное чтение приводят к ошибке, точки не добавляются. Сворачивание не отключает чтение памяти, но клиент может перестать обновлять состояние: отсутствие движения не подтверждает неправильный адрес. Таймаут проверяется между/после синхронных чтений; отдельный вызов Windows ReadProcessMemory принудительно не прерывается. Снимок не атомарен. Это ограничения реализации, не проверенные свойства конкретного клиента.
